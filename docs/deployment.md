# Deployment

## Docker Compose on any host

```bash
cp .env.example .env     # set POSTGRES_PASSWORD
docker compose up -d --build
```

For HTTPS add `DOMAIN=...` to `.env` and use `docker compose --profile https up -d --build`. Port 80 and 443 must be reachable for the certificate challenge.

## AWS with Terraform

What gets created (see `infrastructure/terraform/main.tf`):

- a dedicated VPC with one public subnet and an internet gateway
- a security group allowing only TCP 80 and 443 from anywhere (SSH only if you list CIDRs in `ssh_allowed_cidrs`)
- one `t3.large` Ubuntu 24.04 instance (IMDSv2 required, encrypted root volume) with an SSM role for Session Manager
- a separate encrypted gp3 data volume mounted at `/var/lib/docker`, so Kafka, PostgreSQL and stream state survive instance replacement
- an Elastic IP

Kafka, Redis, PostgreSQL and gRPC are **never** exposed: they only exist on the Docker network.

### Prerequisites

Terraform >= 1.6, AWS credentials with permission to create the resources above, and the repository pushed to a Git remote the instance can clone (default `repo_url` points at this project's GitHub URL; change it for a fork).

### Steps

```bash
cd infrastructure/terraform
cp terraform.tfvars.example terraform.tfvars   # edit region, repo_url, optional domain
export TF_VAR_github_token=...                  # optional, raises the GitHub API limit
terraform init
terraform plan -out tfplan                      # read it; this will create billable resources
terraform apply tfplan
```

The outputs give the public IP and URL. The instance needs a few minutes to install Docker and build the images; follow progress with `aws ssm start-session --target <instance_id>` and `tail -f /var/log/githubpulse-bootstrap.log`.

With a `domain`, create an A record pointing at the Elastic IP after `apply`; Caddy then obtains a certificate. Without a domain the site is served over plain HTTP on the IP address.

### Cost considerations

Approximate on-demand figures for us-east-1 (check the AWS pricing pages, they change):

| Item | Approx. monthly |
|---|---|
| `t3.large` (2 vCPU, 8 GB), 24/7 | about 60 USD |
| 30 GB + 40 GB gp3 volumes | about 6 USD |
| Elastic IP (public IPv4 address charge) | about 4 USD |
| Data transfer out | usually small; first 100 GB per month are free |

A smaller instance will struggle: Kafka, two JVMs, PostgreSQL and Redis need roughly 6 GB. Stop the instance (`aws ec2 stop-instances`) when not demoing; EBS and the Elastic IP keep billing while it is stopped.

### Security notes

- `POSTGRES_PASSWORD` is generated by Terraform and, like the optional GitHub token, ends up in the instance's user data and in Terraform state. Keep state private (use a remote backend with encryption for shared use) and use a revocable, scope-less token.
- The public API is read-only and unauthenticated by design. Add a CDN/WAF for real exposure.

### Cleanup

```bash
cd infrastructure/terraform
terraform destroy          # removes everything, including the data volume and its contents
```

To keep the data, `terraform state rm aws_ebs_volume.data aws_volume_attachment.data` before destroying (and manage the volume by hand afterwards).

## Updating a running deployment

```bash
aws ssm start-session --target <instance_id>
cd /opt/githubpulse && sudo git pull && sudo docker compose up -d --build
```
